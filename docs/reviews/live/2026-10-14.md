## Findings

1. **`agent.prompt` is refused right after `agent.start` (fixed on main, `b387bae`).** On herdr 0.9.4 the socket call `agent.start` returns within a millisecond, before herdr has detected the agent (its server log shows `agent changed` about a second later), while the herdr CLI's own `agent start` waits for readiness (about 4 seconds in a manual run). The branch called `agent.prompt` about a millisecond after `agent.start` and herdr answered `agent <name> is not an active named agent`, so every brief went in by the paste fallback (`launch.inject: paste`, a `prompt_error` effect on the receipt) instead of herdr's prompt path. Nothing was lost: paste worked for both kinds. `b387bae` retries the prompt within `ready_wait` before falling back; the rerun on `main` shows `inject: prompt` and `preambleInput: delivered` for both kinds.
2. **Codex stops at a shared-daemon dialog (open item for the reviewer).** With the Codex desktop app running its shared background server, a plain `codex` start in a pane shows, and waits on, this dialog: `Background server has incompatible feature settings. This session requires api_key_model_discovery to be disabled. Restart will use these shared feature settings: api_key_model_discovery = false, auth_elicitation = true, code_mode_host = true, mcp_oauth_refresh_coordination = false. These settings persist and can disable functionality for other clients. Restart may interrupt active or queued work.` with the options `1. Run without daemon this time`, `2. Restart with these settings`, and `3. Cancel` (the default). Unattended, pod's brief is never typed (`preamble injection typed nothing`) and the start fails at `inject`. The harness launches Codex through a preset with `args = ["--no-daemon"]` (`codex --help`: "Run without the shared background server, even if it is already running"). Side effects: none seen in these cases (every Codex case that reached a worker passed); I did not check whether `codex agents` lists a `--no-daemon` session. Whether pod's built-in `codex` launch table should add `--no-daemon` is for the reviewer: it would fix this machine, and it costs nothing when no daemon runs, but it changes every Codex launch.
3. **`scripts/e2e.sh` and `tests/e2e/session.rs` require herdr exactly 0.9.3 (open item).** This machine runs 0.9.4, so `scripts/e2e.sh` exits at its version check and the e2e `Session` would assert. The live suite accepts any 0.9.x from 0.9.3. The pin in the e2e files is outside lane A6.
4. **Interruption is seen at the next quiet tick, not at the keystroke (by design, recorded for the record).** In case 5 the commit-time attempt is `skipped` because the 3-second quiet window cannot be proven by a command that must not wait; the attempt a minute later, from `check --wait`'s tick, finds the pane quiet with the typed text and records `person is typing: typing here` and the `interruption` category; after `ctrl+u` the following tick delivered the nudge. With no waiting coordinator and no idle hook, a person's typing is therefore noticed only by the tab bar tick (documented as every 30 seconds; not exercised here).
5. **A newer pod migrates the shared store (operational).** While this lane ran, the default store became schema version 3 and every older pod build refused it (`store user_version 3 is newer than supported version 2`), including `pod send` heartbeats from this worker. It cleared once the installed pod was upgraded.
6. **Harness notes.** Claude Code's Bash tool refuses a standalone `sleep N`, so the long command in cases 4 and 7 is `python3 -c 'import time; time.sleep(110)'`. herdr names keys like `ctrl+u`, not `ctrl-u`. Every run removed its trust entries, worktree folders, plugin link, and herdr session; none were left behind.
